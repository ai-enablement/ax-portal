# 대시보드 역할별 조회 범위

- 지정 담당자: Kim, Shari (`shari.kim@changshininc.com`), Kim, Naomi (`naomi.kim@changshininc.com`).
- 최초 DB 구축 시 위 두 계정으로 시작합니다. 이후 Admin & Governance → 계정·역할 → admin 옆 D2B에서 팀장·Admin이 추가·수정·삭제하며 팀원은 조회만 가능합니다. `PORTAL_D2B_DASHBOARD_EMAILS`는 더 이상 사용하지 않습니다. 로그인 및 대시보드 요청마다 DB의 활성 이메일을 정확히 비교합니다.
- 배포 전에 `node --env-file=.env scripts/migrate-d2b-access.mjs`를 실행합니다. 재실행해도 수정·삭제한 기본 계정은 복원되지 않습니다. 삭제는 접근 지정만 비활성화하며 포털 계정/역할은 유지됩니다. 변경 전후 값과 작업자는 audit_logs에 기록합니다.
- 메뉴 갱신은 대상 계정의 새로고침/재로그인이 필요합니다. API 접근 권한은 다음 요청부터 즉시 반영됩니다. 삭제 후에는 기존 포털 역할의 접근 규칙을 적용합니다.
- 서버에서 인증된 포털 계정 이메일을 대소문자 무시·정확히 일치하는 방식으로 확인합니다. 클라이언트 쿼리로 범위를 바꿀 수 없습니다.
- 모든 일반 User는 대시보드 전체 탭에서 DB상 본인이 요구자 또는 Owner인 과제만 조회합니다. 지정 일반 User는 D2B 탭도 보이며, 담당 관계와 무관하게 D2B 전체 과제를 조회합니다. API는 허용된 과제의 일정 요약만 반환하고 문서 원문·이메일은 반환하지 않습니다.
- 일반 User의 전체 탭에는 개발자 필터·그룹 보기와 종료 임박 일정이 없습니다. D2B 탭은 기존처럼 종료 임박 일정을 유지하며 개발자 필터는 없습니다. 집계·간트·과제 상세는 탭에서 허용된 동일 범위를 사용합니다.
- 별도 편집 권한은 부여하지 않습니다. 기존 포털의 다른 기능·과제 권한은 변경하지 않습니다.
- AI 팀원·팀장, Admin, BTS, 비피 솔루션은 D2B 지정 여부와 무관하게 기존 조회 범위·전체/D2B 탭을 유지합니다. D2B 탭에는 개발자 필터와 개발자별 그룹 보기가 없습니다.
